# RankJee — Final blog post template (canonical)

Use this structure for **every** SEO article: local tutoring, exam prep, or product education.  
**Target length:** comparable depth to a parent/guide pillar (~1,200–2,000 words in published body unless the brief says shorter).  
**Voice:** professional, conversational; **you / we**; no filler (“In today’s digital era…”).  
**Formatting:** short paragraphs (2–4 sentences), **bold** for scan lines, lists for steps.

---

## Phase 1 — Strategic Research

Use this exact block at the top of every draft (`.md` content package or editor notes):

### Primary Keyword

* One phrase only — local long-tail when doing city SEO (e.g. `verified CBSE tutor in Satellite Ahmedabad`).

### LSI Keywords

* Five to seven phrases — synonyms, nearby intent, geo modifiers (e.g. `home tuition in [area]`, `best [board] tuition teachers [city]`).

### Search Intent

* Label clearly: **Informational** | **Transactional** | **Navigational**, and note intent strength (e.g. **Transactional (high intent)** when hiring/buying).

### Value Gap Identified

Split into two lists:

**Most articles:**

* What competitors typically do wrong (generic lists, no filters, no verification definition, etc.).

**What we include:**

* Your differentiators: verification framework, parent checklist, trial evaluation, performance tracking, RankJee flows (`/hometutor/`, demos, assessments), etc.

---

## Phase 2 — SEO Metadata

Deliver **before** the main article:

| Field | Rule |
|--------|------|
| **Title tag** | Primary keyword + benefit or audience (e.g. Parent’s Guide); ≤ ~60 characters ideal. |
| **Meta description** | ≤ **155 characters**; outcome + differentiator + geo/exam if relevant. |
| **URL slug** | Lowercase, hyphens, no stop-word stuffing; `/slug-here` style for docs. |

---

## Phase 3 — Article Body (published HTML/Markdown)

### Opening

1. **H1** = primary topic + qualifier (geo, audience, or outcome).  
2. **Hook / pattern interrupt** — stat, bold mistake, or “90% of…” framing (see exemplar posts).  
3. Promise a **system** (steps + criteria), not vague tips.

### Core sections (use H2; use H3 inside steps)

Minimum pillar structure — adapt headings to topic:

1. **Define the core term** (e.g. what “verified” means for tutors; what “mock analysis” means for JEE). Use ✔ checklists where helpful.  
2. **Where to find / how to source** — platforms, local networks, RankJee marketplace; **filters** parents/readers should use.  
3. **Trial / demo — non‑negotiable** — what to observe; optional **quick scorecard** (e.g. clarity / communication / comfort out of 10).  
4. **Questions to ask before paying** — numbered list (e.g. 7 critical questions).  
5. **Red flags** — bullet list (guarantees, no demo, vague answers).  
6. **Comparison** when relevant (e.g. home tutor vs coaching; online vs at‑home) — short, honest trade-offs.  
7. **After hiring / after enrolment — tracking** — weekly/monthly metrics; when to change tutor or strategy.

Optional emoji in H2/H3 **only if** brand voice allows (consistent with published exemplars). Plain headings are fine for formal topics.

### Link sections (required in draft)

**External linking opportunities**

* 2 bullets — authoritative sources (board syllabus, government/education portals, established references). Name *intent*; paste URLs in CMS.

**Internal linking opportunities**

* 2 bullets — placeholders such as `[Internal: RankJee assessment hub]` → `/assessment/`; `[Internal: Book tutor demo]` → `/hometutor/`. Use real routes when publishing.

### Conclusion

* **Actionable**: numbered recap + one strong line on “system beats luck.”

### FAQ

* **3–5 questions** — People Also Ask style; short answers; include money/timing/verification when relevant.

---

## Phase 4 — Quality Control

* **EEAT:** concrete criteria, checklists, and “when to walk away” — not hype.  
* **No plagiarism** — synthesize; quote stats only with a citable source if used.  
* **Anti-AI:** vary sentence length; avoid repeated rhetorical questions.  
* **RankJee:** mention marketplace/demos/practice tests only where truthful for the product.

---

## Output deliverables (per topic)

1. Phase 1 block (keyword + LSI + intent + value gap).  
2. SEO metadata (title, meta ≤155, slug).  
3. Full article + FAQ + link sections.  
4. Publish: paste into `BlogPost` or add a data migration; run `migrate blog` on deploy.
