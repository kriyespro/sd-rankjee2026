GAP-001: NO WALLET TRANSACTION LOG (Critical for a fintech-adjacent product)
  Current: wallet_balance is a single number. Changes are made with add_wallet()
           and direct subtraction in views. No history of what happened.
  Risk: User disputes ("I earned ₹150 but where did it go?"), debugging 
        becomes impossible, fraud detection is impossible.
  Solution:
    New Model: WalletTransaction
      - user (FK)
      - amount (Decimal, can be negative for deductions)
      - transaction_type (EARN_TASK / EARN_REFERRAL / EARN_DAILY /
                          EARN_JACKPOT / DEDUCT_TEST / DEDUCT_WITHDRAW /
                          CREDIT_ADMIN / CREDIT_SIGNUP)
      - reference_id (nullable, points to submission/jackpot/etc)
      - created_at
    Add "Transaction History" tab to profile page and admin dashboard.

GAP-002: NO EMAIL / COMMUNICATION SYSTEM
  Current: Email is literally a TODO comment in tasks.py.
  Risk: Can't re-engage churned users. No OTP for login. No receipts.
  Solution (Lean Bootstrap Approach):
    1. Configure Django email backend with Gmail SMTP (free, instant)
    2. Use Celery task for async sends (already have Celery!)
    3. Build 3 email templates (welcome, daily reminder, payout notification)
    4. Use django.core.mail.send_mail() from within tasks
    Note: No paid email service needed yet. Gmail handles 500/day free.

GAP-003: NO WITHDRAWAL / PAYOUT SYSTEM
  Current: Users earn money in a "wallet" but CANNOT withdraw it anywhere.
  This is a CRITICAL trust issue. Users will churn when they realize there
  is no way to get their money out. This is the #1 reason EdTech earning
  platforms fail in India.
  Solution (Phase 3.1 — URGENT):
    New Model: WithdrawalRequest
      - user (FK)
      - amount (Decimal)
      - upi_id (string — UPI is universal in India, e.g. user@paytm)
      - status (PENDING / PROCESSED / REJECTED)
      - requested_at, processed_at
      - admin_note (for rejection reason)
    Min withdrawal: ₹100 to prevent micro-transactions.
    Admin dashboard: "Pending Withdrawals" section, mark as processed.
    Email notification on status change.
    Start with MANUAL payouts (admin does UPI transfer, marks processed).
    Scale to RazorpayX / Cashfree payout API later.

GAP-004: NO RATE LIMITING / ANTI-ABUSE LAYER
  Current: The ad reward system is protected by a 30-second session check.
           Test cost is deducted via session. Both are bypassable.
  Issues:
    - User can clear cookies, get 3 free trials again
    - Ad reward: No server-side cooldown, only session
    - Task submission: Same user can submit same task once (get_or_create) — 
      good, but no limit on total submissions per day
  Solution:
    - Add server-side cooldown for ads: Last ad claim timestamp in DB, not session
    - Add `trial_tests_used` field to track total trials ever given, not just left
    - Add Django-ratelimit or simple timestamp fields on key actions

GAP-005: PERFORMANCE — N+1 QUERIES IN DASHBOARD
  Current: dashboard/views.py student view runs:
    - UserAttempt queries (multiple)
    - UserSetAttempt queries
    - For each skill in the path: sets + passed_sets (N queries for N skills)
    - Leaderboard query
    - Badge query
    → Easily 20-50 DB queries per page load for active users.
  Solution:
    - Use select_related() and prefetch_related() on all queryset chains
    - Cache the leaderboard with Django's cache framework (5-minute TTL)
    - Cache user's learning path state (invalidate on test submission)
    - Add django-debug-toolbar in dev to measure query count

GAP-006: NO QUESTION EXPLANATIONS (Learning Quality Gap)
  Current: After a test, user sees their score and weak concepts, but NO
           explanation of why the correct answer is correct.
  This is the biggest learning quality gap. Without explanation, the app
  is just a quiz app, not a learning platform.
  Solution:
    Add to Question model:
      - explanation = models.TextField(blank=True)
      - solution_video = FK to ConceptVideo (optional)
    Show in result page: For each wrong answer, show explanation.
    Show option: "Learn why → link to relevant video"
    This is the TRUE test-teach-retest loop.

GAP-007: NO MOBILE RESPONSIVENESS VERIFICATION
  Current: Tailwind CSS is used but no mobile testing is documented.
  The Indian market is 95% mobile-first. The dashboard is a 3-column layout 
  (large screen biased).
  Required: Verify these pages work on 375px (iPhone SE) viewport:
    - Home page
    - Take test page (10 MCQ questions, all options visible without scroll)
    - Dashboard index
    - Earnings page

OBSERVATION-01: THE BUSINESS MODEL CLARITY PROBLEM
  Right now, SkillLoop tries to be:
    (a) A learning platform (videos, tests)
    (b) A gig marketplace (earning tasks)
    (c) A gamification platform (XP, badges)
    (d) An ad-revenue platform (watch ads → earn)
  
  This is NOT a problem — multi-sided platforms work. BUT:
  The earning promise ("earn ₹500/month") must be REAL and DELIVERABLE.
  Currently: There's a "watch ads" feature that gives ₹0.50 per view with
             a 30-second cooldown. To earn ₹100, you need to watch 200 ads.
             That's 100 minutes of ads. This is not sustainable.
  
  CTO Recommendation:
    Pivot the earning model to be SKILL-based, not activity-based:
    - Pass a test → Unlock premium gigs (₹50-₹500 gigs, not ₹0.50 ads)
    - Real gigs: Write an SEO article for a partner brand, 
                 Create a Facebook ad for a local business,
                 Translate content to Hindi
    - Partner with local SMBs / content agencies who need this work done
    - Platform takes 20% commission
    This transforms SkillLoop from "ad-watching app" to "skill-powered gig marketplace"

OBSERVATION-02: THE DAILY JACKPOT IS YOUR BEST RETENTION FEATURE
  The DailyJackpot model is well-designed. But it's hidden behind 
  a "hide from home page" decision (per previous conversation).
  The jackpot at 9:00 PM IST is the single best habit-forming mechanism.
  
  CTO Recommendation:

    → This is the "daily lottery" hook that keeps users coming back.
    → Build a proper countdown, show recent winners, show prize breakdown.

OBSERVATION-03: THE REFERRAL ECONOMICS ARE WRONG
  Current: You give new user ₹50, referrer gets ₹50.
  Problem: Where does this ₹100 come from? The platform absorbs it.
           At 1,000 users with referrals, that's ₹50,000+ in liabilities.
  
  CTO Recommendation (Sustainable referral economics):
    Option A: Give "test credits" not real money. ₹50 worth of test access,
              not withdrawable cash. This reduces payout liability.
    Option B: Only pay referrer when the referred user PAYS (not on signup).
              Referrer gets ₹50 when new user takes their first paid test.
    Option C: Keep current model but cap referral bonuses at 5 per user.
