# RankJee — backup & restore (SSH / Docker)

Adjust DB name / user / password if your `.env` differs from defaults in docker-compose.yml (`rankjee_db`, `postgres`).

## What to back up

| Item              | Why |
|-------------------|-----|
| PostgreSQL        | All app data (users, content, etc.) |
| /app/media        | Uploaded files (media_volume) |
| .env              | Secrets & config (store safely, never commit) |
| Redis             | Usually optional (cache + Celery broker); can be empty after restore |
| Static files      | Optional — run collectstatic again after restore |

---

## Backup (on the server)

SSH in, then:

```bash
cd ~/sd-rankjee2026
mkdir -p ~/backups/rankjee

# 1) Postgres — custom format (good for restore)
docker compose exec -T db pg_dump -U postgres -d rankjee_db -Fc \
  > ~/backups/rankjee/rankjee_db_$(date +%F_%H%M).dump

# 2) Media files (user uploads)
docker compose exec -T web tar czf - -C /app/media . \
  > ~/backups/rankjee/media_$(date +%F_%H%M).tar.gz

# 3) Env (secrets — keep this file private)
cp -a .env ~/backups/rankjee/env_$(date +%F_%H%M).backup
```

Copy backups off the VPS (so a disk loss does not wipe everything):

```bash
# From your Mac:
scp root@161.97.146.14:~/backups/rankjee/rankjee_db_*.dump ~/Desktop/rankjee-backups/
scp root@161.97.146.14:~/backups/rankjee/media_*.tar.gz ~/Desktop/rankjee-backups/
# Do NOT upload .env to public places
```

## Restore (same server or new server)

1) Put files on the server (e.g. ~/backups/rankjee/).

2) Stop workers (avoid writing while DB is replaced):

```bash
cd ~/sd-rankjee2026
docker compose stop web celery celery-beat
```

3) Recreate database and restore:

```bash
docker compose exec -T db psql -U postgres -d postgres -c "DROP DATABASE IF EXISTS rankjee_db;"
docker compose exec -T db psql -U postgres -d postgres -c "CREATE DATABASE rankjee_db OWNER postgres;"

docker compose exec -T db pg_restore -U postgres -d rankjee_db --clean --if-exists \
  < ~/backups/rankjee/rankjee_db_YYYY-MM-DD_HHMM.dump
```

4) Restore media — copy archive into project dir, then:

```bash
docker compose cp ./media_YYYY-MM-DD_HHMM.tar.gz web:/tmp/media.tgz
docker compose exec web sh -c "rm -rf /app/media/* && tar xzf /tmp/media.tgz -C /app/media && rm /tmp/media.tgz"
```

5) Migrate (safe after restore), static, start app:

```bash
docker compose start web
docker compose exec web python manage.py migrate
docker compose exec web python manage.py collectstatic --noinput
docker compose up -d
```

6) Redis — no restore needed for a fresh empty cache/Celery queues.

---

## If pg_restore errors

- Use same Postgres major version (project uses 15).
- If --clean conflicts, drop DB again, CREATE DATABASE, then restore without --clean:

```bash
docker compose exec -T db pg_restore -U postgres -d rankjee_db --no-owner < ~/backups/rankjee/rankjee_db_....dump
```

---

## Checklist

- Test a restore on a copy before relying on backups in production.
- Keep backups off-server.
- Never commit .env to Git; keep encrypted or in a password manager if synced.
